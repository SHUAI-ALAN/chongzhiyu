# 宠之寓设计方案

## 产品定位

宠之寓是一个温暖、可信赖、效率清晰的宠物店微信生态。用户主要在手机端完成“看服务、选时间、预约、购买用品、加入会员”这些高频动作；店员侧后续可扩展后台管理预约、库存和会员。

## 品牌方向

- 店名：宠之寓
- 品牌气质：干净、亲近、专业、有陪伴感
- 核心色：暖珊瑚 `#f97361`、松石绿 `#25b6a4`、墨色 `#263238`
- 辅助色：奶白 `#fff8ef`、浅蓝 `#e7f3ff`、浅绿 `#e8f7f2`
- 视觉语言：圆角柔和但不过度卡通，页面信息密度适中，突出预约效率

## 小程序信息架构

### 首页

- 顶部品牌区：门店名称、营业状态、客服入口
- 快捷入口：预约洗护、寄养、用品、会员
- 推荐服务：用卡片呈现服务时长、价格、适用宠物
- 今日可约：展示最近空闲时段
- 精选用品：展示高复购商品

### 服务

- 按服务分类筛选：洗护美容、寄养托管、健康护理、训练咨询
- 服务卡片包含价格、时长、适用对象、亮点
- 主按钮进入预约

### 预约

- 服务选择
- 宠物信息
- 日期与时段选择
- 用户手机号与备注
- 提交后生成预约单

### 商城

- 分类筛选：食品、护理、玩具、用品
- 商品展示：图、价格、库存状态、标签
- 当前版本做加入购物车提示，后续接支付和订单

### 我的

- 会员等级与积分
- 最近预约/订单
- 优惠券
- 联系门店、导航、客服电话

## 公众号设计

公众号主要承担品牌展示与转化：

- 首屏：品牌承诺、预约按钮、营业信息
- 服务模块：洗护、寄养、护理、用品
- 会员权益：积分、生日礼、寄养优先
- 底部：电话、地址、引导打开小程序

后端预留：

- `GET /wechat/verify` 微信服务器校验
- `POST /wechat/events` 接收公众号事件

## 后端设计

### 数据模型

- `services`：门店服务
- `products`：商品
- `bookings`：预约单
- `coupons`：优惠券
- `orders`：订单摘要
- `members`：会员信息

### 门店后台

门店后台服务店员的日常操作，不做营销型页面：

- 汇总指标：总预约、待确认、已确认、今日预约、未来待服务、公众号线索。
- 预约列表：按状态和日期筛选，查看服务、宠物、客户、备注。
- 状态流转：待确认、已确认、已完成、已取消。
- 公众号线索：查看来自公众号预约提醒表单的手机号和来源。

### API

- `GET /api/config`
- `GET /api/services`
- `GET /api/products`
- `GET /api/coupons`
- `GET /api/slots?serviceId=...`
- `POST /api/bookings`
- `GET /api/orders?phone=...`
- `POST /api/subscribe`

## 迭代路线

1. 当前版本：完成静态体验、API 骨架和预约提交。
2. 第二阶段：接入微信登录、数据库和后台管理。
3. 第三阶段：接入微信支付、订阅消息和公众号菜单。
4. 第四阶段：会员积分、宠物档案、寄养房态和营销活动。
